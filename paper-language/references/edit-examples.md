# Edit Examples

All examples are synthetic teaching material.

## 1. Minimal grammar fix

**Before.** The selector choose the candidate which have highest score, and the update are applied to its state.

**After.** The selector chooses the candidate with the highest score, and the update is applied to its state.

Three agreement errors are fixed inside the original structure. The sentence is shorter and the voice is unchanged.

## 2. Over-editing, rejected

**Before.** We use a small verifier to filter the sampled answers.

**Rejected edit.** To ensure reliability, we leverage a lightweight verification module that carefully filters the sampled candidate responses.

The rejected edit adds a purpose the source never stated, replaces "verifier" and "answers" with synonyms, uses a banned word, and grows the sentence from ten to sixteen words. The original sentence is correct and stays.

## 3. Collaborator wording kept

**Collaborator's sentence.** Scores come from test outcomes, so a wrong answer cannot get credit.

**Edit.** None. The paper usually writes "test-verified scores", and the collaborator chose a near-synonymous description. The sentence is correct. A contradiction would be a reason to change it, and a near-synonym is not.

## 4. Abrupt sentence integrated, with the length paid for

**Before.**
The cache hit rate rises as the workload stabilizes. As described above, the workload stabilizes after the warm-up phase. Eviction decisions differ between the two policies on many keys. Both settings use the same memory budget.

**After.**
The cache hit rate rises once the workload stabilizes after warm-up. This rise depends on which keys stay cached, where the two policies disagree on many keys. Both settings use the same memory budget.

The eviction sentence was abrupt because nothing linked it to the hit rate. The linking clause costs words, and merging the restated second sentence into the first pays for them. The paragraph goes from 36 words to 34.

## 5. Process text deleted

**Before.** Results in this section use the archived run from the previous version, and the final numbers are pending.

**After.** The sentence is deleted. The delivery note lists it, so the user can track which results still need updating.

## 6. Stacked hedges

**Before.** This may potentially suggest that longer contexts could possibly help.

**After.** This suggests that longer contexts help.

One qualifier remains, matching evidence from a correlational analysis. If the evidence were a controlled comparison, "This shows" would be accurate.

## 7. Symmetric contrast

**Before.** The gain comes not from more data but from better data.

**After.** The gain comes from data quality: both settings use the same number of examples.

The contrast is rewritten as the claim plus the fact that supports it.

## 8. Chinese to English

**Source.** 我们发现，在训练后期，模型生成的推理链会逐渐变长，这说明课程调度是有效的。

**Literal draft.** We find that in the late stage of training, the length of the reasoning chains generated by the model gradually increases, which shows that the curriculum schedule is effective.

**After.** Late in training, the model writes longer reasoning chains, which shows that the curriculum schedule is effective.

The revision drops the topic-first order and the nominalization "the length of the reasoning chains". The degree of certainty stays as the source states it. The inference from chain length to effectiveness is stronger than a correlation supports, so the delivery flags it for the author instead of softening it. The paper's terms "reasoning chain" and "curriculum schedule" stay.
