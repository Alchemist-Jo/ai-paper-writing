# 中文技术报告语言规则

本参考用于改写已有技术报告、实验总结、表格和状态说明。所有规则都服从一个上位约束：保持事实、数值、结论和不确定性不变。

## 1. 使用标准术语

已有通用说法时，不另造表述。

| 避免 | 使用 |
|---|---|
| 超长度、超不超长度 | 截断、是否触及长度上限 |
| Ray 的端口会跟自己撞 | 多个任务的 Ray 抢占同一端口 |
| 臂 | 方案 |
| 只看长度那条线 | 长度启发式基线 |
| 刷奖励 | 奖励被优化但评测指标未改善 |
| 存档 | checkpoint |

技术名、模型名和方法名保持原文。不能确认标准译名时，保留可验证的原词并在交付说明中标记歧义。

## 2. 不使用比喻

若读者需要推断指代对象，改为直接说明。

| 避免 | 使用 |
|---|---|
| 血统 | 基座来源 |
| 8 个不同血统 | 8 个不同基座的模型 |
| 已经吃掉一半空间 | 已覆盖一半区间 |
| 变成了一个认题目的检索器 | 退化为问题识别，与学习价值无关 |
| 挑出来的题目看上去健康得多 | 选中问题的截断比例更低 |
| 误差范围还盖着基准线 | 置信区间与基线重叠 |

## 3. 使用中性表头、分类名和状态

优先使用 `问题`、`现象`、`影响`、`结果`、`确认程度`、`实验设置`、`取值数量`、`进行中`。

同一文档的状态标签必须一致。可按实际状态使用：

- `已完成`
- `已确认`
- `未达到基线`
- `结论待定`

不要在后文改用 `做通了`、`意外发现`、`需要修` 等不同口径。

## 4. 不使用“是 X，不是 Y”

直接陈述观测和结论。

| 避免 | 使用 |
|---|---|
| 梯度对齐是噪声，不是信号 | 三项梯度对齐检查结果均在噪声范围内 |
| 买到了基座多样性，但没有买到能力多样性 | 新增模型覆盖了更多基座，但正确率均低于原有区间下界 |
| 稳定是靠粗糙换来的 | 取值数量少的指标重合率高 |
| 越稳定越挑不出东西 | 重合率与取值数量呈反向关系 |

不要仅换连接词后保留同一对比模板。改写为可核验的关系。

## 5. 允许条目只说明发生了什么

表格行不必强行增加数字、比较、原因或结论。例如：

> 对照组为随机选取的 32 个问题。

若该句已完整说明实验设置，不补充不存在的关系。

## 6. 未查明原因时明确标记

来源没有确定原因时，写 `原因未查明`。不要补充未经验证的解释。

| 避免 | 使用 |
|---|---|
| 这可能也解释了前文那个现象 | 该现象与截断的关系尚未验证 |
| 原因不复杂 | 原因未查明 |

后续已有验证证据时，可以保留已确认的机制，但必须与未确认段落区分。

## 7. 不使用口语词

| 避免 | 使用 |
|---|---|
| 赢得很干脆 | 差值为 0.030 |
| 测得更准、测得更糙 | 估计精度更高、估计精度更低 |
| 可选的余地很小 | 候选范围小 |
| 基本上等于抓阄 | 接近随机选取 |
| 白跑、白占 | 无效运行、空占 |
| 一个致命问题 | 主要问题 |
| 有事后找补的嫌疑 | 该切分方式在观察结果之后确定 |

能直接删除且不损失事实的过渡口语应删除。

## 8. 不使用拟人表述

描述对象、操作和测量结果，不赋予系统人的动作或意图。

| 避免 | 使用 |
|---|---|
| 天生需要几百到上千次采样 | 该信号所需的采样量为几百到上千次 |
| 一旦超就制造出参差 | 截断发生时会增大奖励方差 |
| 24 步训练只挪动 0.05 | 24 步训练后正确率变化为 0.05 |
| 超得越彻底反而越稳定 | 截断率越高，奖励方差越低 |
| 回答内容本身的好坏参差 | 答案质量存在差异 |

## 最终检查

1. 逐项核对所有数值、单位、模型名、方法名和状态。
2. 搜索比喻、口语、拟人和 `是…不是…` 句式。
3. 检查表头、分类名和状态标签是否统一。
4. 检查每个因果句是否有来源支持。
5. 对未确认原因使用 `原因未查明` 或直接说明关系尚未验证。
6. 确认没有为了让表格“完整”而补造数字、比较或结论。
